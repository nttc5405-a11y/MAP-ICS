# 案件管制系統（第 1 階段：地圖核心）

指揮所版網頁：建案、底圖、劃區、標點、KML/KMZ/GPX 匯入匯出、事件日誌。
資料存在 Google 試算表與 Drive（GAS 模式），或先存在這台電腦的瀏覽器裡試用（本機試用模式）。

## 一、先在本機試用（不需要 Google）

1. 在這個資料夾開終端機，執行：
   ```
   python -m http.server 8080
   ```
2. 瀏覽器開 `http://127.0.0.1:8080/`
3. 頂列會顯示橘色「本機試用模式」。資料只存在這台電腦的瀏覽器，不會上傳。

> 不要直接雙擊 index.html 開（`file://` 會讓瀏覽器禁用儲存功能）。

## 二、部署 GAS 後端（約 10 分鐘，只做一次）

1. 到 Google 試算表新增一份空白試算表，命名「案件管制總表」。
2. 選單 **擴充功能 → Apps Script**，把 `gas/Code.gs` 全部內容貼進去（取代原本的 `myFunction`），存檔。
3. 上方函式下拉選 **setup**，按「執行」，依畫面授權（會顯示「Google 尚未驗證」→ 進階 → 前往）。
4. 看「執行記錄」，會有一行 **管理權杖（API_TOKEN）**，複製起來。忘了可執行 `showToken`。
5. **部署 → 新增部署作業 → 網頁應用程式**：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   - 按「部署」，複製 **網頁應用程式網址**（結尾是 `/exec`）。
6. 回到網頁，右上角 **設定**：貼上 GAS 網址與權杖 → 測試連線 → 儲存。頂列變綠色「GAS 連線模式」。

之後如果改了 `Code.gs`：**部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選「新版本」→ 部署**，網址不變。

## 三、放上 GitHub Pages

把整個資料夾（`index.html`、`css/`、`js/`）推到 GitHub repo，Settings → Pages → 選 main 分支根目錄。
`gas/` 與 README 放不放都可以（`gas/Code.gs` 不含權杖，權杖只存在 Script Properties 與你的瀏覽器）。

## 第 2 階段：部署與派遣（已加入）

- **部署分頁**：單位（從名冊加入、點「上圖」放到地圖、可拖曳、設帶隊官與狀態）、人員（臨時人員確認／拒絕並編組、撤銷、代為加入）、案件 QR Code、名冊管理。
- **任務分頁**：派遣任務（指派單位或個人、目標區域、危險因子自動帶入）、六種狀態一鍵切換並記錄時間、代登回報。
- **升級既有 GAS**：把新的 `gas/Code.gs` 整份貼上覆蓋 → 部署 → 管理部署作業 → 編輯 → 新版本 → 部署。舊案件第一次開啟時會自動補建新工作表。
- **名冊**：第一次請到「部署 → 人員 → 名冊管理」貼上實際單位與人員（本機試用模式內建的是虛構範例）。

## 第 3 階段：手機現場版（`field.html`）

- **加入**：掃案件 QR → 選單位 → 選姓名（或輸入搜尋，「小明」可找到「王小明」）→ 確認。找不到就以臨時人員加入，等指揮所確認。手機會記住身分，下次一鍵加入。登入 24 小時後失效。
- **兩種檢視**（頂端切換，會記住上次選擇）：
  - 地圖：區域唯讀、我的任務所在區域加粗、顯示自己位置（不回傳）、點區域看危險因子與任務並可「在此回報」、底部抽屜有區域清單。
  - 清單：任務卡片（紅＝新任務、橘＝執行中、綠＝完成）、詳情含帶隊官與成員、時間軸、一鍵狀態（已接收／已抵達／執行中／完成／需支援）。
- **回報狀況**：文字＋最多 3 張照片（自動壓成長邊 1600px、約 300～500KB）＋位置（預設目前 GPS，可拖曳修正）。送出失敗會保留內容，按「重新送出」。
- **提醒**：畫面開著時約每 17 秒檢查一次，有新任務會震動（僅 Android）並顯示紅點。
- **指揮所端**：任務與回報清單可看照片（📷）、在地圖標出回報位置（📍橘點）。
- **權限**：手機只能看自己案件、改自己任務的狀態、新增回報，不能改區域。待確認的臨時人員只能看地圖與區域。
- **本機試用**：指揮所頁與手機頁共用同一個瀏覽器的資料，可在同一台電腦開兩個分頁模擬（QR 連結直接貼到新分頁）。

## 第 4 階段：傷患管制

- **手機回報傷患**（底部「🚑 回報傷患」）：頂部切換「單人／多人」。單人點紅／黃／綠／黑大色塊，加狀況快選（意識清楚、無意識、出血、骨折、失溫…，可複選）與簡述；多人用＋－填各檢傷等級人數。兩種都可附照片（最多 3 張）與位置（預設目前 GPS，可拖曳）。底部「🚑 傷患」分頁看自己回報過的傷患與後送進度（唯讀，後送由指揮所管制；手機只看得到自己回報的傷患）。
- **指揮所「傷患」分頁**：頂部紅黃綠黑人數統計（群體會扣掉已拆出的人，不會重複算）；清單依檢傷輕重排序，未到院在前。
  - 地圖標記：單人＝檢傷色圓點（後送中 ➜、已到院 ✓ 變淡）；群體＝分色圓餅，中央是總人數；標記可拖曳改位置。
  - 後送流程：發現 → 處置 → 後送中 → 已到院，每階段自動記時間；後送中／已到院會詢問車輛與醫院。
  - 群體「拆分」：輸入各色要拆出的人數，系統核對不超過剩餘人數；拆出的個別傷患繼承位置與後送狀態，可各自編輯與後送。
  - 也可由指揮所代為新增、編輯、刪除；「匯出傷患表」輸出 CSV（Excel 可直接開）。事件日誌的時序表照舊可匯出。
- 升級既有 GAS 一樣整份覆蓋 `gas/Code.gs` 並部署新版本，舊案件會自動補建「傷患」工作表。

## 第 5 階段：山域模組（只在「山域」類型的案件顯示「山域」分頁）

- **搜索分區**：地圖上畫多邊形、類別選「搜索區」；屬性可填優先序、地形說明、搜索狀態（未搜／搜索中／已搜）、搜索品質說明。地圖上「搜索中」加粗、「已搜」變淡虛線。「分區」子分頁有進度統計，可一鍵「估算覆蓋率」。
- **軌跡**：匯入 GPX／KML／KMZ 時選類別——計畫路線（失蹤者原定行程）、搜索軌跡（隊伍實際走過，可指定隊伍與所屬分區）、參考軌跡（網路登山紀錄）。勾選「顯示搜索覆蓋範圍」會把搜索軌跡兩側各 50 m 畫成綠帶。
- **覆蓋率估算**：在分區內每隔 10～數十公尺取樣，距任何搜索軌跡 ≤ 50 m 的比例。是估算值，供判斷是否補搜，不是正式測量。
- **登山計畫**（失蹤隊伍原定計畫）：隊伍、領隊、成員（姓名／年齡／電話／經驗）、緊急聯絡人、路線、日程與營地、預計下山、通訊、裝備、衣著顏色。含個資，只有指揮所看得到，手機版不會收到。
- **搜救計畫**：每個作業期（例如一天）一版，各搜索分區指派隊伍、搜索方式、集合與撤離時間；新作業期會帶入上一期的指派；可回顧每日部署。兩種計畫都能「複製文字」貼到 LINE。
- 升級既有 GAS：整份覆蓋 `gas/Code.gs` 並部署新版本。舊案件會自動補建「計畫」工作表與區域的新欄位。
- 尚未做（原設計文件有提）：軌跡時間軸回放、隊伍逾時警示、POD（搜索機率）。

## 第 6 階段：唯讀看板

- **唯讀看板**（「工具」→「唯讀看板（投電視）」）：產生 `board.html` 連結＋QR，深色大字、每 10 秒自動更新，顯示統計、任務、傷患人數、最近回報與地圖。拿到連結的人只能看；**不含人員姓名電話、登山計畫、傷患描述／回報者／照片**。可隨時重新產生（舊連結失效）或關閉。按 F 鍵縮放到全部內容。
- 升級既有 GAS：整份覆蓋 `gas/Code.gs` 並部署新版本，案件索引會自動補上「檢視碼」欄。

## 登入首頁（仿「大傷管理」）

開啟網頁先看到登入首頁，由上而下：
- **👤 姓名**：登入一次，之後自動帶入；寫入事件日誌的「操作者」。
- **🔑 進入既有案件**：選案件＋輸入「案件驗證碼」。知道某案驗證碼的人只能進那一個案件，看不到其他案件。
- **🆕 建立新案件**：案件名稱、類型、地點、設定案件驗證碼（至少 4 字元）、**管理員密碼（＝管理權杖）**。只有知道管理員密碼的人能建案；建立成功後會記住管理員密碼，下次免輸入。
- **📺 只看看板**：選案件＋輸入看板檢視碼（8 碼，在「工具 → 唯讀看板」產生），直接開電視用看板。
- **權限分層**：管理員密碼可進任何案件（驗證碼可留空）、建立案件、維護總表名冊；案件驗證碼只能操作該案（含代為加入人員、派任務等），不能建案或存名冊。
- **舊案件**沒有驗證碼：先用管理員密碼進入，再到「案件 → 編輯資料」設定驗證碼。
- 登出：側欄「案件」分頁的「離開案件（登出）」。重新整理網頁會自動回到上次的案件。
- 練習用：網址後面加 `?local=1` 會強制使用本機試用模式（不碰真實資料）。
- 升級既有 GAS：整份覆蓋 `gas/Code.gs` 並部署新版本，案件索引會自動補上「驗證碼」欄。

### 建案密碼（可開關）
- 總表「設定」分頁有一列 `建案密碼`：
  - **留空＝開放任何人建立案件**，登入頁不顯示密碼欄。
  - **填入文字＝啟用**，一般人建立案件時要輸入這組建案密碼；管理員密碼（管理權杖）永遠可以建案。
- 改了立刻生效、不用重新部署（登入頁約 5 分鐘內更新，重新整理即可）。想關掉就把那格清空。
- 建案密碼與「管理員密碼」是兩回事：建案密碼只能建案，不能進其他案件、不能改名冊；輸入建案密碼不會被瀏覽器記成管理權限。
- 需要更新 GAS。這一列第一次有人開網頁時會自動建立。

### 跑馬燈公告
- 登入頁、指揮所畫面上方、唯讀看板上方會顯示紅色跑馬燈。
- 文字與速度存在總表（Google 試算表）的「**設定**」分頁，**改了不用重新部署**，約 5 分鐘內（看板 1 分鐘內）自動更新：
  - `跑馬燈文字`：公告內容；留空 = 不顯示。
  - `跑馬燈秒數(3-120)`：文字從右跑到左一趟的秒數，**數字越小越快**，預設 18。
- 這兩列在第一次有人開網頁時會自動建立，不用手動新增。

## 編組方案（一個人依任務有不同編組）

- **人員名冊（總表）**：除了固定欄位「人員ID／姓名／職務／排序／啟用」，**其餘每一欄都是一種編組方案**，欄名＝方案名，格內＝該方案下的組別。例如：
  - `消防勤務` 欄：台東分隊、成功分隊…（平常的單位，第一個方案欄＝基本單位；或直接叫「單位」）
  - `人道救援` 欄：管理組、UCC、搜救1組、醫療組、場控組…
  - 想再加一種任務的編組（例：`震災搜救`），在試算表多加一欄、欄名填方案名即可，不用改程式。
- **啟動編組**：進入案件 →「部署 → 人員 → 啟動編組…」→ 選方案 →「啟動」。系統會：①把該方案的每個組別建立成可派遣的單位（待命）；②已在案件裡的人員改歸入該方案的組別；③之後加入的名冊人員自動歸組。任務派遣、防重複派遣、地圖標示都沿用原本的單位機制。
- 不啟動時，人員預設歸在自己的基本單位（和以前一樣）。切換方案前請確認沒有進行中的任務用到舊組別。
- 網頁「名冊管理」的人員表第一行是標題列（單位, 姓名, 職務, 人道救援…），第 4 欄起就是編組方案；沒有標題列時會保留既有的方案欄位。
- 升級既有 GAS：整份覆蓋 `gas/Code.gs` 並部署新版本，案件索引會自動補「編組方案」欄。
- **範例名冊**（34 位虛構人員，含兩種編組方案）：
  - `範例名冊_人員_編組版.csv`：網頁「名冊管理」→ 人員欄下方「選擇檔案」載入，欄位＝消防勤務、姓名、職務、人道救援、震災搜救。
  - `範例名冊_總表貼上用.csv`：欄位順序同總表「人員名冊」分頁（人員ID 留空會自動補），可整張貼進試算表。
  - `範例名冊_單位.csv`：單位類別與車輛（選填，匯入單位用）。

## 其他更新

- **拍照／相簿**：手機回報（狀況、傷患）點「加照片」會先問「📷 拍照」（直接開相機）或「🖼 相簿／檔案」（從手機已有的照片選，可一次選多張）；最多 3 張，超過只取前幾張。
- **案件類型「震災」**：登入頁建立案件可選。危險因子快選會依案件類型提供專屬清單（震災：餘震、建物倒塌、瓦斯外洩、電線斷落、液化、堰塞湖、粉塵／石綿、受困人員等），後面接通用清單。清單在 `js/config.js` 的 `HAZARDS_BY_TYPE`，可自行增減。

## 網頁版也能上傳照片

- 指揮所網頁的「代登回報」「新增／編輯傷患」都有「＋ 加照片」，最多 3 張（傷患編輯時會扣掉已有的張數），選檔後會自動壓縮（長邊 1600px、約 300～500KB）。按「送出／儲存」時先上傳照片再存檔；上傳失敗會保留已填內容，可再按一次。
- 照片存在該案件資料夾的「照片」子資料夾（不公開），任務與傷患清單的「📷 張數」按鈕可查看。
- 需要更新 GAS（新增 `uploadPhoto`）。

## 名冊（只有一張「人員名冊」，不再需要「單位名冊」）

- 單位與組別都由「人員名冊」自動產生，**總表的「單位名冊」分頁已不使用**，可以刪除。單位的車輛不在名冊維護，改到案件裡「部署 → 單位 → 編輯」填。
- 標準版面：`姓名 | 職務 | 消防編組(基本單位) | 人道編組 | 震災搜救 … | 啟用 | 排序 | 人員ID`。人員ID 留空會自動補；「啟用」填是／否。
- **重排版面**：到 Apps Script 編輯器，函式選 `rearrangeRoster` 按「執行」一次，會把現有名冊依標準版面重排並美化（標題色、凍結首列首欄、欄寬、啟用下拉選單、ID 欄淡灰），資料不會遺失。
- 新增人員或新單位／組別：直接在試算表該列填好即可。已啟動編組的案件裡，名冊新增的組別在**有人加入時會自動建立成可派遣單位**，不必重新啟動；也可以再按一次「啟動編組」重新套用。
- 啟動編組後，手機掃 QR 加入頁會改以**該方案的組別**（例：管理組、UCC）顯示，不再是 OO 分隊；沒有啟動方案時維持依基本單位。

## 區域階層（A 區 › A1 作業區）

- 區域可以有「上層區域」。先畫 A～E 區，再在 A 區裡面畫 A1、A2、A3：**畫在某區域裡面時，會自動預選那個區域當上層**（取包住它、面積最小的），也可以在區域屬性的「上層區域」下拉改選；可以多層（A › A1 › A1-1）。
- 新增了區域類別「作業區」（青色），也可以任選其他類別。
- 側欄「區域」清單會把子區域縮排在上層底下（└），上層會顯示「N 個子區域」；篩選類別時改為平面列出。
- 子區域會自動**繼承上層的危險因子**：派任務、游標提示、手機與看板都會顯示「自己＋上層」合併後的危險因子。
- 地圖提示、任務、手機、看板的區域名稱都顯示完整路徑（A區 › A1）。
- 刪除上層區域時，子區域**不會被刪**，會改掛到被刪區域的上一層。
- 需要更新 GAS（區域多一欄「上層區域ID」，舊案件自動補欄）。

## 更新後看到舊畫面？

網頁檔案連結後面帶有版本號（例如 `app.js?v=20261005a`），每次更新程式我會一併換新版本號，瀏覽器就會抓新檔，不會卡在舊版。若手機仍像是舊版，關掉分頁重開，或在瀏覽器設定清除這個網站的快取。

## 已知注意事項

- 底圖：魯地圖正式圖磚（`rudy.tile.basecamp.tw`）已無法連線（瀏覽器回報 SSL 錯誤），改用 OpenTopoMap「地形圖（等高線）」；「魯地圖清爽版」在縮放等級 11 以下圖磚位置不正確，所以小於 11 時自動顯示電子地圖。「Happyman 航跡」只有有人上傳軌跡的地方才有圖磚，其他地方空白是正常的。圖磚來源可能再變動，需要更換時改 `js/config.js`。
- 疊加圖層另有「登山步道（Waymarked Trails）」。
- 全程需要網路（地圖圖磚與 GAS），不做離線。
- 結案後地圖唯讀；後端也會擋下對已結案案件的區域修改。
